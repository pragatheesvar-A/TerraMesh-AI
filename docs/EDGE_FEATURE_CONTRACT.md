# EDGE FEATURE CONTRACT

This document specifies the exact feature order, definitions, and quantization ranges used by the TerraMesh edge/backend inference pipeline, as extracted from the canonical `edge_model_contract.json`.

## 1. Feature Order
The model requires a strict 18-feature input tensor. Firmware (when preparing inference features) and backend ingestion must adhere to this exact ordering:

1. `tilt_x_deg`
2. `tilt_y_deg`
3. `tilt_mag_mrad`
4. `crack_mm`
5. `strain_ustrain`
6. `vib_rms_g`
7. `vib_peak_g`
8. `dom_freq_hz`
9. `band_energy_0_10`
10. `band_energy_10_50`
11. `temp_c`
12. `depth_m`
13. `seam_thk_m`
14. `blast_flag`
15. `rain_flag`
16. `vehicle_flag`
17. `band_ratio_0_10`
18. `extraction_ratio`

## 2. Feature Source & Derivation
* **Direct Telemetry:** Features 1-11 are sourced directly from the Edge Node `NodeTelemetry` LoRa packet.
* **Server-Derived Context:** Features 12-18 (`depth_m`, `seam_thk_m`, `blast_flag`, `rain_flag`, `vehicle_flag`, `band_ratio_0_10`, `extraction_ratio`) are appended at the backend/gateway based on spatial configuration and derived calculations (e.g. `band_ratio_0_10 = band_energy_0_10 / (band_energy_0_10 + band_energy_10_50)`).
* **Aliases:** The wire schema uses `crack_gap_mm` which maps internally to `crack_mm`.
