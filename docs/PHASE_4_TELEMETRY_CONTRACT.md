# PHASE 4 TELEMETRY CONTRACT

This document specifies the exact JSON payload format generated by the edge node firmware (`terramesh_node.ino`) and transmitted over LoRa to the Raspberry Pi Gateway.

## 1. Edge Node Packet Schema
The payload is a compact, flat JSON object. The gateway parses this and forwards it via MQTT to the backend (e.g., `mines/jharia_01/nodes/TM-101/telemetry`).

```json
{
  "node_id": "TM-101",
  "timestamp": "2026-09-25T17:30:20Z",
  "packet_seq": 104,
  "tilt_x_deg": -1.2450,
  "tilt_y_deg": 0.4320,
  "tilt_mag_mrad": 23.100,
  "crack_gap_mm": 2.105,
  "strain_ustrain": 450.20,
  "vib_rms_g": 0.045,
  "vib_peak_g": 0.120,
  "dom_freq_hz": 12.00,
  "band_energy_0_10": 0.0012,
  "band_energy_10_50": 0.0045,
  "temp_c": 27.0,
  "battery_v": 3.95,
  "local_risk": "NORMAL",
  "vib_class": "QUIET",
  "_replayed_from_buffer": false,
  "provenance": "MEASURED EDGE NODE"
}
```

## 2. Sequence and Timestamping
* **Sequence Numbers:** The `packet_seq` is a monotonically increasing unsigned 32-bit integer maintained by the edge node. It is used by the gateway and backend to detect packet loss, duplicate packets (from mesh relays or gateway retries), and packet reordering.
* **Timestamping:** 
  * The `timestamp` is generated on the node using its RTC in ISO-8601 UTC format.
  * If the node RTC is not NTP-synced, it prefixes the monotonic uptime as `"UNSYNCED+12345"`.
  * The Gateway will NOT overwrite the node timestamp. The backend validates and optionally corrects `UNSYNCED` markers upon ingestion using the gateway's receipt time.

## 3. Provenance and Replay
* **`provenance`:** Must explicitly state `"MEASURED EDGE NODE"`. If generated by `gateway_simulator.py`, it states `"SIMULATED EDGE ML"`.
* **`_replayed_from_buffer`:** A boolean flag set to `true` by the edge node if this packet was stored in the node's local LittleFS queue before transmission, indicating possible delay.
